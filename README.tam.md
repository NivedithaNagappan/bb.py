
# bb.py

![Tests](https://github.com/amirouche/bb.py/actions/workflows/test.yml/badge.svg)

**பன்முகத்தன்மையே பலம் என்பதைச் சரிபார்க்கக்கூடியதாக மாற்றுதல்.**

உங்கள் மொழியில் ஒரு function எழுதுங்கள். அதே சிந்தனை வேறொருவருக்கும் — மனிதருக்கோ அல்லது இயந்திரத்திற்கோ — தோன்றியிருந்தால், அதன் hash அதை வெளிப்படுத்தும்.

> **சோதனை முயற்சி**: இந்த மென்பொருள் ஆராய்ச்சிக்காக உருவாக்கப்பட்டு, தொடர்ந்து மேம்படுத்தப்பட்டு வருகிறது.

ஒத்திசைவு கண்டறியப்படுகிறது; வேறுபாடுகள் பாதுகாக்கப்படுகின்றன. இரண்டு சிந்தனைகள் ஒரே logic-ஐ எழுதும்போது, அவற்றிற்கு ஒரே hash கிடைக்கும். ஒருவரையொருவர் கண்டறிய பொதுவான மொழி தேவையில்லை. அவர்கள் வெவ்வேறு logic-ஐ எழுதினால், வெவ்வேறு hash-கள் கிடைக்கும்; இரண்டும் பாதுகாக்கப்படும். எதுவும் ஒரே ஆங்கிலப் பதிப்பாக மாற்றப்படுவதில்லை.

```python
# Français
def additionner(premier, second):
    """Additionner deux nombres."""
    somme = premier + second
    return somme
```

```python
# العربية
def اجمع(الأول, الثاني):
    """اجمع عددين."""
    الناتج = الأول + الثاني
    return الناتج
```

```python
# Español
def sumar(primero, segundo):
    """Sumar dos números."""
    suma = primero + segundo
    return suma
```

```bash
bb add additionner.py@fra   # → one hash
bb add اجمع.py@ara          # → the same hash
bb add sumar.py@spa         # → the same hash again
```

மூன்று நபர்கள் அல்லது இரண்டு நபர்களும் அரபு மொழியில் prompt வழங்கப்பட்ட ஒரு AI மாதிரியும் இதைச் செய்யலாம். யாரும் மொழிபெயர்க்கவில்லை; ஒவ்வொருவரும் தங்களுக்கென ஒரு புதிய function-ஐ எழுதினர். பெயர்களும் docstring-களும் அவரவர் மொழியிலேயே இருக்கும். Hash என்பது logic-ஐ மட்டுமே அடிப்படையாகக் கொண்டு கணக்கிடப்படுகிறது.

## ஏன்?

மாணவர்கள் ஆங்கிலத்தில் coding கற்றுக்கொள்கிறார்கள்; ஆனால் தங்கள் சொந்த மொழியில் சிந்திக்கிறார்கள். அவர்கள் தேர்ந்தெடுக்கும் ஒவ்வொரு பெயரும் எழுதப்படுவதற்கு முன்பே ஒரு மொழிபெயர்ப்பாக மாறுகிறது. அதே பொருளைக் கொண்டிருந்தாலும், அரபு எழுத்துமுறையைப் பயன்படுத்தும் மொழிகளுக்கு LLM-களில் அதிக tokens தேவைப்படுவது வழக்கம். ஏற்கனவே கூடுதல் சுமையைச் சந்திப்பவர்களுக்கு இது அமைதியான கூடுதல் செலவாகிறது.

இயந்திரத்தின் பார்வையிலும் இதே கேள்வி வேறொரு கோணத்தில் எழுகிறது. பல LLM agents ஒரே பிரச்சினையில் பணிபுரியும்போது, அவை உண்மையிலேயே ஒரே கருத்தை ஏற்றுக்கொள்கின்றனவா அல்லது ஒரே மாதிரியாகப் பேசுகின்றனவா என்பதை யாராவது கண்டறிய வேண்டும். Logic ஒன்றாக இருக்கும் சூழலில் ஒரே hash என்பது எளிமையான மற்றும் நேர்மையான பதிலாகும். Logic வேறுபட்டால், நேர்மையாக "இல்லை" என்று தெரிவிக்கிறது.

இந்தத் திட்டம் இன்னும் ஆரம்ப நிலையில் உள்ளது. துல்லியமான பொருத்தமே அடிப்படை; நெருக்கமான பொருத்தங்களைக் கண்டறிவது இன்னும் ஆராய்ச்சி நிலையில் உள்ள கேள்வியாகும் (`LIMITS.md` பார்க்கவும்).

## இது வழங்கும் சாத்தியங்கள்

bb.py என்பது சரிபார்க்கக்கூடிய, பராமரிக்கக்கூடிய, ஆசிரியரின் உரிமையையும் அதன் தோற்ற வரலாற்றையும் பாதுகாக்கும் வகையில் content-addressed அறிவைப் பகிர உதவும் ஒரு கருவியாகும்.

- **உங்கள் மொழியில் சிந்தியுங்கள்** — எந்தவித அபராதமும் இன்றி உங்கள் தாய்மொழியில் variable பெயர்களையும் ஆவணங்களையும் எழுதலாம்.
- **மொழிகளைக் கடந்து பகிருங்கள்** — `bb show hash@lang` மூலம் எந்த மொழியிலுள்ள function-ஐயும் பெறலாம்.
- **அடையாளத்தைச் சரிபாருங்கள்** — யார் எழுதியிருந்தாலும், எந்த மொழியில் எழுதியிருந்தாலும், ஒரே logic எப்போதும் ஒரே hash-ஐ உருவாக்கும்.
- **தோற்ற வரலாற்றைப் பாதுகாக்குங்கள்** — ஒவ்வொரு function-ஐயும் கண்காணிக்க முடியும்; யார் எதை உருவாக்கினார், யார் யாருடைய பணியை அடிப்படையாகக் கொண்டு உருவாக்கினார் என்பதையும் அறியலாம்.
- **இணைத்து உருவாக்குங்கள்** — ஒரு pool-இல் உள்ள மற்ற function-களைப் பயன்படுத்தி புதிய function-களை உருவாக்கலாம்; அவற்றின் dependencies கண்காணிக்கப்பட்டு, compile செய்யப்பட்டு, இயக்கப்படலாம்.
- **ஒரே கோப்பு, கூடுதல் dependencies இல்லை** — முழுக் கருவியும் ஒரே Python கோப்பில் உள்ளது.

## இது எவ்வாறு செயல்படுகிறது?

```
Source code → Parse to AST → Normalize → Hash → Store
```

Normalization செயல்முறை அனைத்து local variables-க்கும் ஒரு பொதுவான பெயரிடும் முறையைப் பயன்படுத்துகிறது, imports-ஐ வரிசைப்படுத்துகிறது, மேலும் hashing செய்வதற்கு முன்பு docstrings-ஐ நீக்குகிறது. Built-in பெயர்களும் imports-உம் மறுபெயரிடப்படுவதில்லை.

இதன் விளைவாக, ஒரே logical structure கொண்ட எந்த function-க்கும், அதன் ஆசிரியர் பயன்படுத்திய பெயர்கள் எதுவாக இருந்தாலும், ஒரே SHA-256 hash கிடைக்கும்.

அசல் பெயர்கள், docstrings மற்றும் மொழி தொடர்பான metadata ஆகியவை hash-உடன் சேமிக்கப்படுகின்றன — ஒவ்வொரு மொழிக்கும் தனித்தனி mapping இருக்கும். இதன் மூலம் அடையாளம் (logic) மற்றும் வெளிப்படுத்தும் முறை (மொழி) ஆகியவை தனித்தனியாகப் பாதுகாக்கப்படுகின்றன.

துல்லியமான பொருத்தமே அடிப்படை. இரண்டு நபர்கள் தனித்தனியாக ஒரே logic-ஐ எழுதும்போது, அந்த hash அதை நிரூபிக்கிறது. இரண்டு நபர்கள் ஒரே பிரச்சினைக்கு வெவ்வேறு முறைகளில் தீர்வு காணும் நடைமுறைச் சூழலில், semantic search நெருக்கமான பொருத்தங்களைக் கண்டறிகிறது: ஒரே மாதிரியான அமைப்பு, ஆனால் வெவ்வேறு தேர்வுகள்.

ஒத்திசைவு கட்டாயப்படுத்தப்படுவதில்லை; அது கண்டறியப்படுகிறது. Hash என்பது சந்திக்கும் இடமாக அமைகிறது. ஒரே பிரச்சினைக்குத் தீர்வு காணும் தனித்தனி குழுக்கள், முன்கூட்டிய ஒருங்கிணைப்பு இல்லாமலேயே, ஒரே அடையாளத்தின் மூலம் ஒருவரையொருவர் கண்டறிய முடியும்.

## அறிமுகம்

சரிபார்க்கக்கூடிய அறிவுப் பகிர்வின் மூலம் பன்முகத்தன்மையே பலம் என்பதை அங்கீகரிக்கும் ஒரு சமூகத்தை வளர்ப்பதே இதன் நோக்கமாகும்.

Content-addressing ஒவ்வொரு function-க்கும் ஒரு தனித்துவமான அடையாளத்தை வழங்குகிறது. ஆசிரியரின் உரிமை பாதுகாக்கப்படுகிறது. அதன் தோற்ற வரலாற்றைக் கண்காணிக்க முடியும். யார் எதை உருவாக்கினார் என்ற தகவலை இழக்காமல் அறிவைப் பகிர முடியும்.

## தொலைநோக்குப் பார்வை

bb.py என்பது Möbius என்ற திட்டத்தை நோக்கிய ஒரு படியாகும். இது timestamps மூலம் தோற்ற வரலாற்றை வெளிப்படுத்தும் மற்றும் பெயர்கள் பலமொழிப் பதிவேட்டிற்கான பார்வைகளாக அமையும் content-addressed மொழியாகும்.

யார் எதை உருவாக்கினார், யார் யாருடைய பணியை அடிப்படையாகக் கொண்டு உருவாக்கினார், யாருடைய பணியை உரிய அங்கீகாரம் அளிக்காமல் பயன்படுத்தினார் என்பதைக் கண்டறிய இது உதவும்.

இந்த அமைப்பு எந்த விதிமுறைகளையும் கட்டாயப்படுத்துவதில்லை; நீதியையும் அமல்படுத்துவதில்லை. ஆனால் நடந்தவற்றை மறந்துவிட அனுமதிப்பதில்லை.
